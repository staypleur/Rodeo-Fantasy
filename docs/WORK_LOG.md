## 2026-10-06 — 앰버랫 탑승·포획 첫 프로토타입

### 확정된 답변
- 첫 몬스터는 앰버랫: 근접형, 불/포유류 시너지.
- 스킬은 전방의 적 1명에게 불꽃 이빨로 물기. 총기력 40, 일반 공격 4회 후 스킬 사용.
- 3m는 점프 거리다. 범위 내 몬스터를 클릭해 줄을 던지고 탑승한다.
- 탑승 중 자동 전진, A/D 좌우 이동을 적용한다.
- 왕복 막대에 스페이스바 1회 입력. 흰색이면 낙하 후 재도전, 노란색이면 추가 미니게임 없이 5초 후 포획, 주황색이면 즉시 포획한다.

### 구현
- 확정 내용을 기획서와 공용 설정에 반영했다.
- 서버의 거리/장애물/점유 검사, 점프와 줄 표시, 자동 이동, 포획 상태 전환을 구현했다.
- 한국어 안내, 카운트다운, 포획 막대, 거리 표시, 이번 접속 포획 수를 구현했다.
- 최초 85/14/1, 재포획 80/17/3 비율을 적용했다.
- `dist/RodeoFantasy-Capture.rbxlx`와 초보자용 `docs/STUDIO_SETUP.md`를 추가했다.
- 앰버랫의 최종 외형을 임의로 정하지 않고 이름표가 있는 회색 기능 테스트 블록을 사용했다.
- 이동/막대 속도와 점프 연출 시간은 `Config.Prototype`의 테스트 조정값으로 분리했다.

### 검증
- Luau 판정 테스트 26개, 소스 4개 컴파일, 공용 로직 정적 분석, 배포 파일 구조 및 소스 일치 검사 통과.
- 경계값 검사에서 재포획 주황색 시작점의 부동소수점 오차를 찾아 수정했다.
- 실제 설치된 Roblox Studio에서 배포 파일 로드, 공용 모듈 실행, 계층 구조, 모델 위치 이동 검증 통과.
- 실제 Studio Play 모드의 서버/클라이언트 자동 검사 13개 통과. 거리 거절, 탑승, 이동, 세 가지 포획 판정, 중복 입력 방지, 재포획 비율을 확인했다.
- 검사 결과와 남은 수동 확인 항목은 `docs/VALIDATION.md`에 기록했다.

### 남은 범위
- 외형, 정식 지역, 전투 실행, 영구 데이터 저장은 아직 구현하지 않았다.
- 사용자 플레이로 이동 속도, 막대 속도와 조작감을 확인하고 조정한다.

## 2026-10-06 — 이동 속도 조정 및 연속 미니게임 요청

- 사용자 피드백: 현재 속도가 너무 느리며, 한 번에 잡히지 않으면 미니게임이 계속되어야 한다.
- 테스트 전진 속도를 18 → 40 studs/s(약 2.2배), 좌우 이동을 12 → 22 studs/s로 조정했다.
- 연속 미니게임과 기존 노란색 5초 포획의 관계는 확인 중이다. 타이머 유지/재시작/자동 포획 제거 중 원하는 방식을 질문했다.
- 답변 전에는 포획 규칙을 임의로 바꾸지 않는다. 이번 파일에는 이동 속도 조정만 반영한다.

## 2026-10-06 — 5초 동안 이어지는 포획 미니게임

- 사용자 확정: 노란색은 5초 동안 버티는 판정이며 미니게임은 계속 진행된다. 추가 노란색이 5초를 초기화하지 않는다.
- 첫 노란색의 포획 종료 시각을 따로 저장하고, 기존 막대의 왕복 시각을 그대로 유지하도록 수정했다.
- 버티기 중에도 스페이스바를 처리한다. 노란색은 유지, 흰색은 낙하 및 포획 취소, 주황색은 즉시 포획한다.
- 화면의 막대를 유지하고 남은 시간과 연속 판정 안내를 표시한다.
- 이전에 높인 전진 40 / 좌우 22 studs/s는 유지한다.
- 로데오 스탬피드의 공식 소개에서 달리며 동물을 타고 길들이는 흐름을 참고했다. 색상 판정과 5초 규칙은 사용자의 기획을 따른다.
- 참고: https://apps.apple.com/ca/app/rodeo-stampede-sky-zoo-safari/id1047961826
- 문법/배포 구조 검사와 기존 판정 로직 26개 검사 통과. 연속 노란색, 버티기 중 흰색·주황색, 포획 취소를 Studio 플레이 검사에 추가했다.
- 실제 Studio Play 모드의 수정된 검사 20개 통과. 반복 노란색에도 종료 시각이 같으며, 버티기 중 흰색/주황색 판정도 적용됨을 확인했다.

## 2026-10-06 — 몬스터 동물원 운영으로 기획 변경

- 사용자 요청: 전투를 없애고 몬스터 동물원을 열어 몬스터가 생성하는 돈을 버는 구조로 변경한다.
- 진화 시점을 5성/10성에서 3성/6성/9성으로 변경한다. 진화하면 외형이 더 예쁘거나 멋있어지며 동물원 수익도 증가한다.
- 메인·서브·고대 시너지를 모두 폐기한다. 관련 전투 분류, 기력, 공격 스킬 데이터와 UI 표시도 제거했다.
- 기존 최대 10성과 동일 몬스터 3마리를 모으는 성장 규칙은 변경 요청이 없어 유지했다.
- 이전 보스 전투와 보스 전투 기반 지역 해금 규칙은 폐기하고 대체 방식은 미정으로 남겼다.
- `Config.Growth`에 확정된 성장 기획을 기록했다. 동물원과 수익/진화 동작 자체는 아직 구현하지 않았다.
- 수익 금액·주기·수령 방식, 동물원 배치, 진화 외형은 사용자 확인 후 구현한다.
- 기획서, 안내 문서, 테스트 설정, Studio 배포 파일을 함께 갱신한다. 과거 작업 이력은 위에 보존한다.
- 검증: 포획 규칙 검사 25개, 변경된 공용 설정/클라이언트 문법 검사, 배포 파일의 구조 및 원본 소스 일치 검사 통과. 실행 코드와 배포 파일에 이전 전투/시너지 표시가 남지 않았음을 확인했다.

## 2026-10-06 — 직접 수령과 유료 자동 수령 확정

- 사용자 확정: 동물원 수익은 기본 직접 수령, 자동 수령은 유료 기능으로 제공한다.
- 기획서와 프로젝트 안내에 반영했다.
- 자동 수령 가격, 영구/기간제 여부, 적용 범위는 미정이다. 수익 생성 주기, 직접 수령 조작, 누적 한도와 오프라인 수익도 아직 확정하지 않았다.
- 이번 변경은 문서 기록이며 수익 생성이나 결제 기능을 구현/등록한 것은 아니다.
- 검증: 문서 변경 내용과 공백 오류를 확인했다. 실행 코드 변경은 없어 게임 테스트는 재실행하지 않았다.

- 내장 이미지 생성 도구로 기본형 A/B/C 비교 시안을 제작하고 `assets/concepts/emberrat-base-options-v1.png`에 저장했다. 생성 프롬프트도 함께 보관했다.

## 2026-10-07 — 앰버랫 B 기본형 모델 적용

- 사용자 확정: 불꽃을 추가한 시안 B로 제작한다.
- 날렵한 체형, 큰 귀, 긴 꼬리, 주황빛 갈색/크림색, 머리와 꼬리 끝의 작은 불꽃을 Roblox 기본 부품으로 제작했다.
- 포획 테스트 장소의 회색 블록을 모델로 교체하고, 재사용할 수 있는 `dist/Emberrat-B.rbxmx`도 생성한다.
- 모델 형태/색상은 `tools/emberrat_model.py`에서 수정할 수 있다. 외부 에셋 업로드나 플러그인은 필요하지 않다.
- 기존 탑승 기준점을 보이지 않는 `MountRoot`로 유지하여 외형 전체가 함께 움직이게 구성했다.
- 화면의 ‘테스트 블록/외형 미정’ 안내를 현재 모델에 맞게 수정했다.
- 기본형 제작 범위이며 진화 외형과 달리기 애니메이션은 아직 제작하지 않았다.
- 검증: 포획 규칙 25개, Luau 컴파일, 배포 파일/개별 모델의 XML 참조와 소스 일치 검사 통과. 실제 Studio에서 구형 메시, 불꽃 크기/열, 기본 부품의 비충돌 설정, 전체 모델 이동 후 상대 위치 유지 검사를 통과했다.
- 미완료 검증: 최신 모델의 Studio Play 자동 검사에서는 결과가 `nil`로 반환되어 성공을 확인하지 못했다. 화면 캡처 자동화도 완료되지 않아 실제 렌더링/조작은 수동 확인 항목으로 남긴다. 이전 블록 버전의 Play 20개 검사 결과와 구분해 기록했다.
- 적용 안내: 기존 Studio 탭을 닫고 최신 장소 파일을 다시 연 뒤 F5로 실행한다. 다른 장소에는 개별 모델 파일을 삽입할 수 있다.
- 저장 상태: 모델·코드·문서의 로컬 저장 및 최종 XML/공백 검사 완료. 자동 승인 검토가 사용량 한도 오류로 실패하여 권한이 필요한 검사용 Studio 종료 명령은 실행되지 않았다. 이번 작업은 아직 커밋/원격 푸시하지 못했으며, 승인 검토가 복구된 뒤 진행해야 한다.
- 후속 처리: 사용자의 다음 단계 요청 후 승인 검토가 정상 처리됐다. 최종 XML/참조/소스 일치 및 공백 검사를 재확인하고 `fc642ba`로 커밋해 GitHub `main`에 푸시했다. 위 업로드 미완료 상태는 해소됐다. 다음 동물원 기능은 배치 방식, 직접 수령 조작, 테스트 우리 개수와 기본 수익을 질문했으며 답변 전에는 확정하지 않는다.
