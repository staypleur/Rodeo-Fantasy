# 카페·부화소 검토 파일 사용법

이번 파일은 **Studio 검토용**입니다. 코드/원본 메시 검사와 오프라인 배치 렌더는 완료했지만, Studio 실플레이·20명 동시 접속·실제 기기 성능·게시 서버 간 이동은 아직 검증하지 않았습니다. 공개 서버에 덮어쓰기 전에 아래 순서로 확인하세요.

## 열 파일

프로젝트 폴더 `dist/LocalOperator` 안의 다음 파일은 기존 운영자 설정을 보존합니다. 현재 열려 있는 예전 파일을 덮어쓰지 않았습니다.

- `RodeoFantasy-Social-Operator-Hatchery.rbxlx`: 기존 로비 8명 + 알 부화소 + 교배 선택 화면 + 카페 이동 입구.
- `RodeoFantasy-Social-Operator-Cafe.rbxlx`: 별도 카페 20명용. 실내·테라스·축구장·놀이터, 소환/탑승/프로필/거래 검토.

공유용은 `dist/RodeoFantasy-Social-Hatchery.rbxlx`, `dist/RodeoFantasy-Social-Cafe.rbxlx`입니다. 개인 운영자 비밀번호/인증 설정은 공유 파일에 추가하지 않습니다.

1. Roblox Studio에서 **정지**를 누릅니다.
2. **파일 → 파일 열기(Ctrl+O)**로 위 카페 파일을 엽니다. 탐색기 `Workspace → RodeoCafe`에 저장된 카페가 보입니다.
3. 아래 모스랫 설치 후 **Play**를 누릅니다. 카페 앞 테라스에서 시작하는지 확인합니다.
4. 공개하지 않은 로컬 파일은 테스트용 임시 가방입니다. 운영자 버튼으로 `/monster 모스랫 1` 등을 입력하고 기존 비밀번호 창에서 인증해 확인할 수 있습니다.

## 모스랫: 사냥터 3k / 카페 10k

`assets/meshes/meshy` 폴더의 **Mossrat_S1_Hunt_Rigged.glb**(3,114삼각형), **Mossrat_S1_Detail_Rigged.glb**(10,348삼각형)를 사용합니다. 기존 정적 GLB에는 새 다리 뼈가 없으므로 새 파일을 가져와야 합니다. 같은 외형·UV·텍스처 위에 걷기용 뼈를 추가했습니다. 앉기/눈 감기/교감 애니메이션까지 완료된 모델은 아닙니다.

1. 재생을 정지한 상태에서 **파일 → 3D 가져오기(Import 3D)**로 두 파일을 각각 가져옵니다. 메시 합치기는 끄고 모델·텍스처를 Roblox에 업로드하고 Workspace에 추가합니다. 가져오기 중 앞/위 축을 임의로 변경하지 마세요.
2. 탐색기에 `Scene`으로 보이면 각각 이름을 **Mossrat_Hunt**, **Mossrat_Detail**로 바꿉니다. 가져온 외형을 직접 회전하지 마세요.
3. 두 모델을 Ctrl로 함께 선택합니다. **보기 → 명령 표시줄**에서 다음 코드를 실행합니다.

```lua
require(game.ReplicatedStorage.RodeoFantasy.MeshyMossratInstaller).installSelected()
```

4. 출력에 설치 완료가 나오면 **Ctrl+S**. 두 가져온 전시 모델은 설치 후 Workspace에서 지워도 됩니다.
5. **로비 파일과 카페 파일 양쪽에** 이 작업을 합니다. 운영자 가방 지급 → 소환/사냥으로 얼굴 방향, 다리 움직임, 발 접지, 안장 위치를 확인합니다.

준비 파일은 이미 얼굴이 **-Z**를 보도록 회전했습니다. 설치기에서 추가 180도 회전을 하지 않습니다. 원본 Meshy 파일은 +Z이므로 이 안내에 섞어 사용하지 마세요. 원본을 직접 설치해야 할 때만 `install(source, source, "+Z")`를 사용합니다. 실제 Studio 가져오기 설정이 다르면 다시 화면 확인이 필요합니다.

## 새 로비 상공 모델

사용자 원본의 복사본 **assets/meshes/meshy/LobbyAirship_Source.glb**를 사용합니다. 10,293삼각형, 원본 텍스처 보존, 리깅 없음입니다. 이전 자체 제작 고래 초안으로 덮어쓰지 않습니다.

1. 로비 **Hatchery** 파일을 열고 재생을 정지합니다.
2. **파일 → 3D 가져오기**로 위 파일을 업로드하고 Workspace에 추가합니다. 앞/위 축과 모델 회전을 바꾸지 않습니다.
3. 가져온 모델 한 개를 선택하고 명령 표시줄에서 실행합니다.

```lua
require(game.ReplicatedStorage.RodeoFantasy.MeshyAirshipInstaller).installSelected()
```

4. 설치 완료 메시지 후 **Ctrl+S**. 기존 상공 모델은 `ServerStorage → MeshyAirshipBackup`에 보존됩니다. 발판·사다리는 유지하고 실제 메시 아래에 네 줄을 연결합니다.
5. **Play**로 얼굴 방향·배 아래 줄·발판 통행을 확인합니다. 현재 리깅 없는 한 메시라 전체의 느린 유영만 연결합니다. 개별 지느러미/꼬리 변형은 추가 리깅이 필요합니다.

GLB를 로컬에 준비한 것과 Roblox 업로드/설치 완료는 다릅니다. 이 작업 환경에서는 계정 대신 자산 업로드나 Studio 실행을 하지 못했습니다.

## 조작과 확인

- 로비 내 구역 입구 **E 길게 → 알 관리 → 부화소 1~4**. 알은 칸당 1개. 교배 시간/결과가 미정이므로 현재 알이 없는 것이 정상입니다.
- 가방 **진화 옆 교배**: 암컷·수컷 선택, 다른 종류 가능, 최대 4팀 조건 검증. 실제 시작은 **준비 중**입니다.
- 카페 **R → 몬스터 카드에 마우스 → E 1초**: 소환. 터치는 카드의 소환 버튼을 길게 누릅니다. 소환은 한 마리만, 소유 개체는 가방에 남습니다.
- 내 몬스터 몸 옆 **Q 1초**: 탑승. **WASD/조이스틱** 이동, **Q** 내려오기. 타인 몬스터는 탑승할 수 없습니다. 실내에 들어가지 않는 큰 몬스터는 운동장에서 소환합니다.
- 카페 **T 1초** 또는 상단 프로필 지정 버튼: 보유 몬스터 최대 5마리 지정.
- 다른 사람 근처 **E 1초**: 아바타·대표 몬스터·도감·거래. Studio의 **테스트 → 서버 및 클라이언트**로 2명을 실행해야 상대 기능을 확인할 수 있습니다.
- 거래는 상대 수락 → 양쪽 제안 → 제안 확인 → 양쪽 최종 확인. 제안이 바뀌면 확인이 초기화됩니다. 양쪽 모두 내놓아야 하며 돈만 서로 교환하는 거래는 안 됩니다. 취소·거리 이탈·퇴장 시 닫힙니다.
- 가방의 모든 몬스터가 카페에서도 돈을 생산합니다. 소환 여부와 무관합니다.

## 게시 후 카페 연결

카페 Place는 아직 없으므로 이동 입구에 준비 안내가 나옵니다.

1. Studio의 **파일 → Roblox에 게시(다른 이름으로 게시)**에서 **기존 Rodeo Fantasy 경험**을 선택하고 **새 Place**로 카페를 추가합니다. 기존 로비 Place를 덮어쓰지 마세요.
2. Creator Dashboard에서 각 Place의 서버 정원을 **로비 8명 / 카페 20명**으로 설정합니다.
3. 새 카페 Place ID와 로비 Place ID를 확인한 뒤 두 파일의 `ReplicatedStorage → RodeoFantasy → SocialConfig`에 `CafePlaceId`, `LobbyPlaceId`를 동일하게 설정하고 게시합니다. ID를 보내주시면 코드 쪽 설정을 이어갈 수 있습니다.
4. 두 Place는 **같은 경험**이어야 가방 저장소를 공유합니다. 다른 경험으로 만들지 않습니다. 공개 서버의 가방은 저장 실패 시 빈 데이터로 덮어쓰지 않고 접속을 중단합니다.
5. Roblox 앱으로 로비 → 카페 → 로비 이동 및 재접속 후 보유 몬스터·돈을 확인합니다. Studio에서는 실제 서버 이동이 작동하지 않습니다.
6. Studio **경험 설정 → 커뮤니케이션**에서 음성 채팅을 활성화합니다. 이용자는 Roblox에서 음성 채팅 사용이 가능한 계정이어야 합니다. 모든 이용자에게 마이크 사용을 강제하거나 보장하지 않습니다.

공식 문서: [Place 이동](https://create.roblox.com/docs/projects/teleport), [음성 채팅](https://create.roblox.com/docs/chat/voice-chat), [데이터 저장](https://create.roblox.com/docs/cloud-services/data-stores).

Studio 저장 테스트를 할 때는 별도 테스트 경험에서 API 서비스 접근을 켭니다. Studio 데이터는 `_Studio_v1`, 공개 데이터는 `_v1` 저장소로 분리합니다. 실제 다중 서버 실패·모바일/PC 성능 테스트는 남아 있습니다.
