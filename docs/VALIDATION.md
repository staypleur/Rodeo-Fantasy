# 첫 포획 프로토타입 검증

## 자동 검사

현재 기획은 가방 수익과 펫 동행으로 변경됐다. 우리 계산 모듈과 테스트는 제거하고 `tests/bag_rules.luau`로 대체했다. 이전 우리 계산 20개 검사는 과거 버전의 결과다. 가방 수익의 실제 화면/플레이 검증은 아래 수동 확인 항목에서 진행한다.

가방 계산 15개 검사, 기존 포획 규칙 25개 검사, 게임 소스 5개 컴파일, 배포 파일 XML 참조 및 내장 소스 일치 검사 통과. 새 수익 연결 후 Studio Play 검사는 아직 수행하지 않았다.

2026-10-08 영상 참고/갈아타기 버전: 소스 6개 및 확장한 Play 검사 코드 컴파일, 배포 파일 참조/소스 일치 검사 통과. Studio에서 다리 움직임, 탑승 원점 불변, 정지 자세 복원 검사도 통과했다. 갈아타기의 실제 Play 자동 검사는 90초 이상 기다려도 결과를 확인하지 못했으며 통과로 기록하지 않는다.

2026-10-07 사용자가 선택한 앰버랫 B 기본형으로 테스트 모델을 교체했다. 포획 규칙·변경 코드의 컴파일·배포 파일 검사를 재실행했으며, Studio에서 새 모델의 구조와 전체 이동을 검증했다.

- Luau 실행기로 포획 구역 경계, 최초/반복 구역 비율, 막대 왕복, 3m 범위, 잘못된 거리 값 등 **25개 검사 통과**. 전투 폐기에 따라 기존 기력 검사는 제거했다.
- 클라이언트, 서버, 공용 모듈 총 4개 Luau 소스의 컴파일 통과.
- 공용 모듈과 판정 테스트의 Luau 정적 분석 통과.
- 배포 파일 XML 구조, 참조 중복 여부, 스크립트 배치, 원본 코드 4개와 내장 소스의 일치 검사 통과.
- 설치된 Roblox Studio의 CLI에서 실제 배포 파일 로드와 공용 모듈 실행, 스크립트 계층, 모델 이동 검사 통과 (`tests/studio_smoke.luau`).
- 앰버랫 B의 큰 귀·꼬리 부품, 2개 불꽃 효과, 탑승 기준점, 전체 모델 회전/이동 후 상대 위치 유지, 모든 부품의 고정/비충돌 설정 검사 통과.
- 개별 모델 파일의 참조 완결성 검사 통과. 모델만 삽입해도 다른 장소 파일이나 업로드된 메시를 요구하지 않으며, 실행 스크립트는 포함하지 않는다.
- 이전 블록 모델 버전은 실제 Studio Play 모드에서 **20개 검사 통과** (`tests/studio_playtest.luau`): 기본 탑승·이동·포획 흐름과 함께 버티기 중 막대 표시, 연속 노란색 판정, 최초 5초 종료 시각/막대 시작 시각 유지, 버티기 중 주황색 즉시 포획, 흰색 낙하 후 지연 포획 방지를 확인했다.
- B 모델 적용 후 Play 자동 검사를 재시도했지만 `ExecutePlayModeAsync`가 결과 문자열 대신 `nil`을 반환했다. 이번 버전의 Play 검사 통과로 취급하지 않는다. 모델 구조 검사는 통과했으며, 실제 외형과 탑승 조작은 아래 수동 항목에서 확인해야 한다.
- 플레이 자동 검사는 임시 서버/클라이언트 스크립트로 RemoteEvent를 호출한다. 실제 마우스·키보드 입력의 체감과 화면 배치는 아래 수동 항목으로 확인한다. 검사 전용 스크립트는 배포 파일에 포함하지 않는다.

## 수동 조작으로 확인할 항목

자동 검사와 별도로, 실제 마우스·키보드 조작과 화면을 확인하기 위한 목록입니다.

- [ ] F5로 캐릭터, 모래 바닥, 앰버랫 B 모델, 한국어 안내가 표시된다.
- [ ] 3m 밖에서는 탑승하지 못하고 가까이 가라는 안내가 나온다.
- [ ] 3m 안에서 클릭하면 줄이 표시되고 점프해 탑승한다.
- [ ] 탑승 후 자동 전진하며 A/D로 좌우 이동한다.
- [ ] 실제 탑승 시점부터 3초 후 미니게임이 시작된다.
- [ ] 흰색 판정은 즉시 낙하하고, 다시 탑승해 재도전할 수 있다.
- [ ] 노란색 판정은 5초 후 정확히 한 마리를 추가한다.
- [ ] 5초 버티기 중 막대가 계속 움직이고 스페이스바 입력이 가능하다.
- [ ] 두 번째 노란색은 남은 시간과 막대 위치를 초기화하지 않는다.
- [ ] 버티기 중 흰색은 낙하하고, 이전 5초가 지나도 포획 수가 늘지 않는다.
- [ ] 버티기 중 주황색은 남은 시간을 기다리지 않고 포획한다.
- [ ] 주황색 판정은 즉시 정확히 한 마리를 추가한다.
- [ ] 한 번 포획한 후 다음 시도에 80/17/3 구역이 보인다.
- [ ] 스페이스바를 연타해도 중복 포획되지 않는다.
- [ ] 캐릭터 리셋 후 정상 이동하고 다시 탑승할 수 있다.
- [ ] 두 플레이어가 동시에 같은 몬스터를 탈 수 없다.
- [ ] Stop 후 다시 Play하면 포획 수가 0이다.
- [ ] 큰 귀, 크림색 얼굴/배, 긴 꼬리, 머리/꼬리의 작은 불꽃이 보인다.
- [ ] 포획하면 가방 마릿수가 증가하며 배치 없이 2초마다 한 마리당 1원이 쌓인다.
- [ ] 두 마리 이상을 잡으면 각자의 포획 시점을 기준으로 수익이 쌓인다.
- [ ] 캐릭터 리셋은 가방/수익을 유지하고, Stop 후 Play는 초기화한다.
- [ ] 높은 탑승 카메라에서 앞길이 보이고 다리가 움직인다. A/D에 따라 몸이 기울고, 낙하하면 정지 자세로 돌아온다.
- [ ] 바닥 표식이 뒤로 지나가며 클릭/이동을 가로막지 않는다.
- [ ] 미니게임 전 3초 동안 3m 안의 다른 몬스터 클릭으로 갈아타며 이전 몬스터는 포획되지 않는다.
- [ ] 새 탑승 이후 3초부터 다시 세며 미니게임/5초 버티기 중에는 갈아탈 수 없다.
- [ ] 거리 밖/다른 플레이어 점유/장애물 등 실패한 요청은 기존 탑승과 남은 시간을 유지한다.
- [ ] 여러 번 갈아탄 후 흰색 낙하/캐릭터 리셋에도 이동이 정상 복구된다.

## 알려진 범위와 후속 검증

- 포획 수는 서버 메모리에만 있으며 영구 저장을 구현하지 않았다.
- 서버가 거리, 장애물, 점유 상태, 생존 상태, 입력 단계와 빈도를 확인한다. 클라이언트의 성공 판정이나 포획 수는 받지 않는다.
- 현재 서버 수신 시각으로 판정한다. 인터넷 지연이 큰 환경의 좁은 주황색 구역 판정은 보정 설계와 추가 테스트가 필요하다.
- 탑승 이동은 평지용이며 장애물 회피, 언덕, 정교한 리깅, 몬스터 간 충돌 처리는 이후 범위다. 기본 다리 움직임은 클라이언트에서 계산하며 탑승 기준점은 바꾸지 않는다. 작은 불꽃에는 Roblox 기본 효과를 사용한다.
- 영구 보유 목록, 펫 소환/동행, 직접 수령 조작, 진화, 지역 해금, 결제, 모바일 조작은 아직 구현하지 않았다. 동물원 배치와 전투는 개발 계획에서 폐기했다.

## 개발용 재실행

```text
python tools/build_place.py
python tests/check_place.py
luau tests/capture_rules.luau
luau-analyze src/shared/Config.luau src/shared/CaptureRules.luau tests/capture_rules.luau
```

Windows Luau 실행기가 한글 경로를 처리하지 못하면 `src`와 `tests`를 임시 영문 경로에 복사해서 검사한다. 이는 검사 도구의 파일 경로 문제이며 프로젝트 파일 이름을 바꿀 필요는 없다.
